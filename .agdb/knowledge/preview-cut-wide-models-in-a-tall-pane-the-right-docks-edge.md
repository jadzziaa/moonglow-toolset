- The owner's installed Moonglow 4.2.1+753023de (19 Nov) framed by a sphere fitted to the vertical 20 deg alone: `radius / sin(20 deg) * 1.1`. In a tall, narrow Preview (wide layout, or the 280-320 dock beside a form) a wide model (TDoD's dd_bca_cart*, a long table) was cut at the sides. U11 (3add227e) already replaced it with `fitting_distance` (each point's across and up, aspect-aware, ROOM 1.08), the same as mgv's `frame_tight`. Break 1 in target/m5/W8/breaks.txt puts the old fit back.
- A real fault remained: `ModelView::refresh` rebuilt the model for a changed appearance (Appearance changed in its form) and kept the distance framed for the old one. Now it calls `frame()` again when `framed` and the source is a blueprint (`!model`): a camera moved by hand stays, and a model's own file read again keeps its camera (gpu_memory's test holds that).
- Thumbnails, galleries and pickers frame through `mg_preview::compose::framed_on` at aspect 1.0 in square cells: a different path and correct. W6's shared picture is letterboxed into the second pane, keeping it whole.
- egui's Panel resize handle is 3 points either side, but widgets drawn later (the editor area: a form's scroll area) take the hover over the outer side, so beside a blueprint form only 2.5 points showed the cursor; a floating form's Preview pane (`window_panes`' right panel) had 3. Fix: `shell::edge_seam`, an interact made after the central area (`right_edge_seam` from lib.rs; `window_edge_seam` from tabs.rs) by the pattern of the dock's other seams (`column_seam`, `section_seams`, mg-ui's own in shell.rs, not the kit's): 6 points, ResizeHorizontal, a lit line. It senses `Sense::DRAG` alone: in egui 0.36 `Sense::drag()` is DRAG | FOCUSABLE, and the seam, made last in the window, joined the Tab order and scrolled Module Properties away (table_panels' grid-keys test). `column_seam` and `section_seams` in shell.rs had the same fault and got `Sense::DRAG` in W8's fix round (test `preview_panel::tab_passes_the_right_dock_s_seams`). Any new seam: `Sense::DRAG`, never `Sense::drag()`. Its id `right-dock-edge`.with("seam") is excluded in right_dock.rs `dock_wrong` like egui's edge.
- A floating form's Preview pane: 280 to 60% of the window, kept for the run only (not in settings); the Right Dock: 280 to two fifths, saved; under 1400 held at 280; folded, a strip.
- Turning (W8's fix round, review C's W8-1, the owner's ruling "preview turn: a"): `fitting_distance` is now yaw-free. Each point becomes the ring it sweeps about the target's up line ((horizontal distance, height) pairs); the need per yaw is convex in those, so only the convex hull's corners (`hull_of`) are fitted, each ring at 72 points (5 deg). A turn by drag or arrow keys never carries a framed model out, and the distance stays the same while turning (test `preview_panel::a_framed_model_stays_whole_as_it_turns`: plank and long table framed at yaws 60, 0, -30, 90 in a 319x864 Preview, a whole turn in 15 deg drags). Before, the plank framed end-on reached -1.3..2.3 of the width when turned. (The first round's claim of the long table showing about 15% smaller was a guess from a picture; measured in the 320 Preview it is about 1%, the wagon about 4%.) Moonglow Viewer's `frame_tight` still fits the current yaw only and centers in the view's axes, so mgv frames a long model tighter and a turn there can still cut it.
- Thumbnails and gallery cells (`mg_preview::compose::framed_on`) don't turn and keep the per-yaw fit.
- Tests can find a seam as a widget in `ctx.viewport(|v| v.prev_pass.widgets)` with `sense == Sense::DRAG` (egui's panel edge senses `click_and_drag`; a `Window`'s own edges are `Id::new(layer).with("edge_drag").with(side)`, also DRAG alone, so exclude them).

- Second fix round (review D) and the owner's ruling "fit: b" (2026-11-22): the yaw-free fit holds at the framing pitch only; in a wide picture (906x631) a vertical drag carried the plank to 1.33 of the half-height. A fit over every pitch too (±1.45, steer's clamp) was built and measured, then taken back: it made the commoner (nw_comfemale) fill 0.64 of the tall Preview's height against the Creature board's 0.8, and the long table 0.73 as big in a wide picture. The owner chose every yaw at the opening tilt only, knowing a steep tilt can cut a long model in a wide picture (no deferred entry: it is the ruling). Rejected too: a bounding sphere, which equals the pitch fit in a wide picture and is far smaller in a tall one (obelisk 0.44, commoner 0.55), since a point's across part depends only on yaw. Built: `Fit` (model_view.rs), made once by `Fit::of(target, points, pitch)` in `frame()` and kept; `Fit::distance(aspect)` gives a new shape's distance from the kept up need and one (toward, across) line per hull-ring point, so a dock drag's refit (`ModelView::refit`) reads no points (review D measured 1.7 ms per frame for 50,000 points before; the new timings are owed at the release gates). A model's file read again (`refresh`'s `model` path, camera kept) drops the kept fit (test a_model_read_again_is_framed_anew_by_its_new_points). Gotcha: rewriting a file in the override reloads resources and reopens the view (framed anew), so that path is reached only through the workspace (`ws.module.set`). Sizes are measured exactly by an oracle in screens.rs `w8_fit_sizes`/`w8_needed` (least distance with `pick::project` keeping all of `reached()` inside with the 1.08 room); framed equals its every-yaw rule within 0.002 (target/ui-mock/impl/m5-w8/fit-b/). The fit is as tight as turning allows: some yaw brings the model to 1/1.08 of the half picture; `swept` and `whole` (`nearest_over_turns`) check > 0.88. Breaks 18-22 in target/m5/W8/breaks.txt (18, pitch ignored, is caught only by the unit test: the app's views open at 20 deg). Tests: model_view::tests::the_fit_holds_the_points_at_every_turn; preview_panel's a_framed_model_stays_whole_as_it_turns, a_model_in_a_wide_picture_stays_whole_as_it_turns (states the ruling: tilted, the plank reaches past), the_arrow_keys_turn_a_framed_model_whole (Left/Right whole, Up/Down distance only), the_hak_editor_s_preview_stays_whole_as_it_turns, the_gallery_s_preview_stays_whole_as_it_turns.
